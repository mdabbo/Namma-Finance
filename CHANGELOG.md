# Changelog

All notable changes to NAMAA Finance are documented here. Versions follow Semantic Versioning.

## [0.7.0] - 2026-07-29

Interface redesign, development-database rebase, and post-redesign audit
remediation. The migration chain that builds the schema was replaced and then
carried forward to schema **27**, so **existing development databases must be
deleted and recreated** — see below.

### Added

- **Six-section navigation** — Overview, Projects, Finance, Team, Reports,
  Settings — with nested section navigation, breadcrumbs, active-route
  highlighting, a command palette (Ctrl+K), and correct Arabic RTL and English
  LTR layouts. Every previous route still resolves through redirects.
- **Design system**: typography, spacing, radius, shadow, and status scales
  behind consistent Button, IconButton, Input, Select, MoneyInput, DateInput,
  Modal, Drawer, Table, Badge, Alert, KPI card, EmptyState, and PageHeader
  components, in light and dark themes.
- **Redesigned dashboard**: four headline KPIs (contract value, total cash in,
  outstanding receivables, net cash position), an Attention Required section
  that links to the matching filtered page, cash-in/cash-out and project-health
  charts, recent activity, and top active projects.
- **Project workspace**: one page with six tabs — Summary, Contracts, Finance,
  Team, Time, Documents — replacing the previous tab sprawl. Engineers see only
  the operational tabs.
- **Finance workspace**: a Finance Overview plus Certificates, Payments,
  Expenses, Receivables, and Cash Flow. Receivables are a first-class page with
  overdue and project scoping and a record-payment action.
- **Data tables** gain spreadsheet-safe CSV export and saved views that restore
  search, sorting **and page filters**, enabled on Projects, Clients,
  Certificates, Payments, Expenses, Receivables, People and Time entries.
- **Guided onboarding**: six steps from company profile to first contract,
  skippable and resumable, with progress derived from real records rather than
  stored as a checklist.
- **Demo workspace**: optional, clearly marked sample data created through the
  real repositories — so numbering, audit evidence, and payment-driven
  certificate statuses are genuine — removable from Settings.
- **Playwright UI suite**: 99 tests across 1366×768, 1440×900, and 1920×1080
  covering the full client-to-payment cycle, expenses, team, time, navigation,
  language and theme switching, onboarding, saved views and CSV export,
  project-workspace routing, and eight visual regression states. The suite runs
  in GitHub Actions on every push and pull request.

### Changed

- The development migration chain `0001`–`0024` is consolidated into
  `0001_baseline.sql` and `0002_seed_reference_data.sql`. The baseline was
  generated by replaying the real chain and verified object-for-object against
  it, recreating schema **24**. Forward-only migrations then carry it to **27**:
  assignment lifecycle (25), cancellation evidence integrity (26), and truthful
  audit application version (27). The baseline files are never edited, so
  recorded migration checksums stay valid.
- Backup validation now checks migration lineage, not just schema version.

#### Post-redesign audit remediation

- **Rust owns payment-driven certificate status.** The payment commands no
  longer accept a status derived by the frontend; create, update and void
  recalculate the affected certificates from stored evidence inside the same
  transaction that writes the payment. Collection evidence can no longer promote
  a SUBMITTED certificate past approval. One shared fixture file is asserted by
  both the Rust and TypeScript engines so the two cannot drift.
- **Explicit assignment lifecycle** (ACTIVE / COMPLETED / CANCELLED) separate
  from archiving, which is visibility only. Cancelling drops the unearned
  remainder of the commitment while preserving earned and paid history. The
  frozen earned figure is derived under the global financial lock and is
  immutable once written, so it cannot be rewritten without evidence.
- **Accurate lifecycle wording.** The interface no longer says "Delete" for
  operations that archive or void — the schema forbids deleting any primary
  record. Each dialog states the real effect, and payment, expense and
  certificate voids record a reason that reaches the audit log.
- **Truthful cash KPIs.** The headline is Total Cash In, not "Cash Collected",
  with certificate collections, advances, retention releases and unallocated
  customer credit reported beside it. Collected cash is valued at the rate
  effective when the cash arrived, so the components reconcile to the total.
- **URL-driven project workspace.** Tab and finance subview live in the URL, so
  refresh, browser history and shared links all work. Tabs a role may not open
  are refused by the parser, not merely hidden.
- **Reports holds reporting only**; the import wizard and payment-integrity
  review moved to Settings › Data Tools, and Settings became one linkable
  section at a time with role access enforced per section.
- Money the financial read model has not produced yet is reported as unknown
  rather than as zero, on screen and in CSV exports.

### Fixed

- Finance lists excluded archived projects inconsistently with the dashboard,
  so an archived project's certificates were listed with net payable and unpaid
  shown as zero.
- CSV export wrote integer minor units into money columns, overstating exported
  amounts a hundredfold.
- The project workspace formatted missing read-model figures as money, showing
  a consolidated payment amount and team payout balances of zero while the
  audited snapshot was still loading.
- Demo-workspace removal aborted on the first record the user had already
  archived, stranding the remaining sample records permanently.

### Security

- The end-to-end database and app-lock bridges are restricted to the dev server,
  so no build can ship a bundle whose data layer is an HTTP endpoint or whose
  Argon2 lock gate is bypassed.
- Pre-rebase backups are rejected before any file is replaced, instead of
  restoring a database the migration plugin then refuses to open.

### Database reset required

Development databases built by the retired migration chain are **not
upgradeable and were not migrated**. The migration plugin rejects the changed
lineage and the application will not start until the old database is removed:

```
%APPDATA%\com.mepfinance.app\mep-finance.db
```

Delete or move that file and start the app; a clean database is created
automatically. Backups taken before this release restore only into a pre-rebase
build. The complete pre-rebase source and migration history is preserved at the
git tags `pre-db-rebase-v0.6.7` and `pre-ui-redesign-v0.6.0`. Full detail in
`docs/DATABASE-REBASE-0.7.0.md`.

### Release status

This build is a **Beta** release. It is not represented as production-ready and
must not be relabelled Stable without explicit approval and a passing release
checklist. Known limitations are listed in
`docs/releases/0.7.0/KNOWN-LIMITATIONS.md`.

## [0.6.0] - 2026-07-22

### Added

- Transactional financial mutation boundaries and explicit payment-allocation integrity.
- Contract revisions and immutable historical commercial-term snapshots.
- Separate cash, accrual, committed, and forecast financial definitions.
- Immutable audit history, hardened backup/restore, application security controls, managed documents, sync-conflict review, and transactional numbering.
- Deterministic financial property tests, coverage thresholds, and Windows CI quality gates.
- A single release manifest, release-channel indicator, and visible application/schema versions.

### Security

- Restrictive Tauri CSP and filesystem capabilities.
- Argon2id application lock with retry throttling and fail-closed corrupt-state handling.
- Backup integrity, checksum, schema, and foreign-key validation.

### Release status

This build is a **Beta** release. It is not represented as production-ready; release approval requires the checklist and all P0 data-integrity gates to pass.
